## Context

Phase 5 (`improve-llm-code-generation`) froze canonical imports and hosted
`llms.txt` / `llms-full.txt` on GitHub Pages. Agents that already retrieved
IterableData now copy the right snippet. Agents that search MCP registries,
skill directories, or `/.well-known/llms.txt` still miss it.

## Goals / Non-Goals

- Goals:
  - A committed MCP `server.json` that matches the official 2025-12-11 schema
    for a PyPI stdio server
  - Docs-site crawler files (`.well-known/llms.txt`, `robots.txt`) identical to
    the root machine index
  - Heuristic prompt coverage over the public corpus (skill, llms-full, cookbook)
  - A few more prompt-shaped cookbook scripts that run without optional extras
- Non-Goals:
  - Publishing to the official MCP registry from CI (needs publisher credentials)
  - Paid / live LLM generation evals
  - A CLI
  - Changing `iterable.mcp` tool names or JSON envelopes

## Decisions

- Decision: MCP server name is `io.github.datenoio/iterabledata`. PyPI identifier
  is `iterabledata` (the extra `[mcp]` is documented in `websiteUrl` / description).
  `runtimeHint` is `uvx`. Version in `server.json` MUST equal `iterable.__version__`.
- Decision: `.well-known/llms.txt` is a byte-for-byte copy of root `llms.txt`,
  generated by `dev/scripts/generate_llms_txt.py` into `docs/static/.well-known/`.
- Decision: Prompt-eval concatenates skill + `llms-full.txt` + cookbook sources
  and asserts required substrings per prompt. No network, no API keys.
- Decision: External directory submissions (Context7, skills.sh, MCP registry)
  are documented in `docs/docs/integrations/DISCOVERY.md`; CI does not log in.
- Alternatives considered: Generate `server.json` at release only. Rejected —
  crawlers and the registry want a file in the default branch.

## Risks / Trade-offs

- `server.json` version can drift from `__version__` → CI assertion
- `.well-known` under Docusaurus `baseUrl` `/iterabledata/` is site-relative,
  not `https://datenoio.github.io/.well-known/` (org root is out of this repo)
